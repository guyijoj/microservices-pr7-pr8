# Практическая работа №8 — тестирование микросервисов

**Основа:** исходный код 7-й практической из `Практика_7_код.zip` (четыре сервиса: orders, payments, deliveries, notifications). Код 7-й практической не переписан. Добавлены тесты, `pytest.ini` и этот файл.

## 1. Соответствие методичке

Методичка (печатная страница 55) требует выбрать **два из трёх** видов тестирования. Выбраны:

1. **Unit** — отдельные Pydantic-модели, функции бизнес-логики и обработчики событий. Для них используется `FakeTx`: in-memory имитация `UnitOfWork` без PostgreSQL, HTTP и RabbitMQ.
2. **Компонентное** — HTTP-роутеры FastAPI с настоящей сериализацией, авторизацией, валидацией и обработкой ошибок. Используется `TestClient`, отдельные временные БД SQLite и `httpx.MockTransport` вместо внешнего HTTP. Передача событий в компонентных тестах происходит вызовом настоящего `handle_event`, а не через RabbitMQ.

**Дополнительно** подготовлены тесты реальных контейнеров (`tests/e2e`), которые выполняются **только** при `PR8_LIVE=1`. Они проверяют HTTP по `localhost:8001–8004` и, в полном сценарии, реальный RabbitMQ и PostgreSQL. Без запущенного Docker они пропускаются и не считаются выполненными.

## 3. Запуск на MacBook (Terminal)

Открой Terminal и перейди в папку `prak7`, **куда распакован полный проект**. Пример, если папка в «Загрузках»:

```bash
cd ~/Downloads/prak7
```

Если распаковал в другом месте, открой папку `prak7` в Finder, перетащи её в Terminal после команды `cd ` и нажми Enter.

Создай отдельное окружение Python и установи зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

**Запусти сначала unit-тесты:**

```bash
python -m pytest tests/unit -v
```

Ожидается **89 passed**, если версии и исходники соответствуют предоставленному архиву. Этим тестам не нужны запущенные контейнеры.

**Затем компонентные тесты:**

```bash
python -m pytest tests/component -v
```

Ожидается **39 passed**. Docker тоже не требуется — используется TestClient и временные SQLite-базы. Но библиотеки из `requirements-dev.txt` должны быть установлены, включая `aio-pika` (этот пакет импортируется приложением).

**Все тесты исходников + новые:**

```bash
python -m pytest tests/unit tests/component tests/test_workflow.py -v
```

При эквивалентных зависимостях и исходном коде ожидается **133 passed** (89 новых unit, 39 новых компонентных, 5 существовавших тестов ПР7).

> Слово «ожидается» важно: успех локальной проверки не означает, что тесты уже выполнены на компьютере пользователя. Результаты необходимо получить самостоятельно.

## 4. Отдельная проверка реальных Docker-контейнеров

Необходимы запущенный Docker Desktop и проект ПР7 в этой же папке. Выполни:

```bash
docker compose up --build -d --wait
docker compose ps
PR8_LIVE=1 python -m pytest tests/e2e -v
```

Ожидается **14 тестовых случаев**, если все приложения, PostgreSQL и RabbitMQ действительно работают. Порты по `compose.yaml`: Заказы 8001, Платежи 8002, Доставка 8003, Уведомления 8004, RabbitMQ 15673. Тесты создают собственные новые заказы и платежи с уникальными ключами, **данные других пользователей и тома Docker не удаляют**.

Реальная проверка Docker пока **не выполнялась** в среде подготовки; её результат нужно получить на MacBook с запущенными контейнерами. Если внешний сервис недоступен или RabbitMQ не обработал событие в установленный лимит, тест завершится с ошибкой.

Чтобы остановить контейнеры без удаления баз:

```bash
docker compose stop
```

Не используй `docker compose down -v` для подготовки скриншотов: параметр `-v` удаляет данные в томах.

## 5. Что показать на защите

- **Unit:** пример проверки `CreateOrder`, диапазона количества 1–99 и подсчёта 2 × 55000 + 15000 = 125000 копеек; проверка невозможности подтвердить неоплаченный заказ.
- **Mock/Fake:** `FakeTx` заменяет БД на словарь в памяти, `httpx.MockTransport` заменяет HTTP-переход к другому сервису. Тесты не зависят от доступности PostgreSQL или сети.
- **Компонентное:** `TestClient` посылает POST `/api/orders`, проверяет ответ `201`, `Location`, вычисленную сумму и статус; тестирует 401, 403, 404, 409 и 422.
- **События:** `handle_event` выполняет смену статуса, формирует доставку и уведомление. Повтор `event_id` не дублирует обработку благодаря `_inbox`.
- **Docker (по возможности):** реальный переход оплаченного заказа `awaiting_payment` → `paid` через RabbitMQ и последующее создание доставки/уведомлений.

## 7. Ограничения

- Демокаталог и токены использованы **строго из исходников ПР7**: `dish-1 = 55000` и `dish-2 = 15000` копеек, `restaurant-1`, `customer-bocharov`, `restaurant-demo`, `courier-demo`, `service-demo`.
- Маршрут команд Заказа — `/api/orders/{order_id}/commands/{action}` (не синтаксис `:confirm` из ПР6).
- У ПР7 отсутствует отдельный HTTP `/health`: для проверки готовности реального контейнера использован `/openapi.json`.
- В `requirements-dev.txt` исходного проекта уже есть `pytest` и необходимые зависимости приложения. Устанавливать ничего поверх глобального Python не надо — используй `.venv`.
- На этапе подготовки выполнено **89 unit + 39 компонентных + 5 исходных тестов = 133 успешных тестовых случая**; контейнерные тесты (**14**) не выполнялись. Компонентные тесты в локальной среде проверены с технической подменой отсутствовавшего пакета `aio_pika` при импорте; ни один метод брокера не вызывался. В стандартном окружении проекта пакет устанавливается из `requirements-dev.txt` и подмена не нужна.
